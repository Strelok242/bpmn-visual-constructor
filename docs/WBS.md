# Иерархическая структура работ (ИСР)

Модель жизненного цикла: последовательное уточнение требований и архитектуры с итерационной реализацией, проверкой и подготовкой выпуска. Глубина декомпозиции: проект → этап → пакет работ → результат.

| Код ИСР | Пакет работ | Результат | Связанная ветка Git |
|---|---|---|---|
| 1.0 | Управление проектом | Репозиторий, план, контроль изменений | `main` |
| 1.1 | Формулирование цели и границ | Паспорт и требования | `feature/requirements` |
| 1.2 | Пользовательские сценарии | Перечень функций, критерии приёмки | `feature/requirements` |
| 2.0 | Проектирование | Концептуальная модель | `feature/model` |
| 2.1 | Модель элементов и связей | Данные `nodes` и `flows` | `feature/model` |
| 2.2 | Ограничения, геометрия | Валидация и координаты | `feature/model` |
| 3.0 | Реализация | Работающий прототип | `feature/ui` |
| 3.1 | HTML/CSS интерфейс | Палитра, инспектор, рабочая область | `feature/ui` |
| 3.2 | SVG редактор | Отрисовка и перетаскивание | `feature/ui` |
| 3.3 | Пользовательские команды | Связи, удаление, история, сохранение | `feature/ui` |
| 4.0 | Экспорт данных | BPMN XML и JSON | `feature/xml-export` |
| 4.1 | XML-модель элементов и связей | Экспортируемая BPMN-модель | `feature/xml-export` |
| 4.2 | BPMN Diagram Interchange | Координаты узлов и потоков | `feature/xml-export` |
| 5.0 | Испытания и передача | Тесты и инструкции | `docs/verification` |
| 5.1 | Модульные проверки | Протокол `npm test` | `docs/verification` |
| 5.2 | Браузерная приёмка | Фактические скриншоты UI | `docs/verification` |
| 5.3 | Документация | README, архитектура, роли, публикация | `docs/verification` |
| 5.4 | Публичное размещение | Репозиторий GitHub с URL | **выполняется владельцем аккаунта** |

**Последовательность:** 1.1–1.2 → 2.1–2.2 → 3.1–3.3 → 4.1–4.2 → 5.1–5.4. Проверка интерфейса может выполняться итерационно после 3.0 и 4.0. Ветки Git отражают группы работ, но не заменяют иерархию ИСР.
